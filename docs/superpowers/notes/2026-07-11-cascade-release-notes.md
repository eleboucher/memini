# Namespace cascade: release notes (PR-description fodder)

memini's release notes are generated by `git-cliff` from conventional commit
messages (`.forgejo/workflows/release.yml` → `cliff.toml`), so there is no
manual `CHANGELOG.md` to hand-edit. This file is source material for the PR
description on the namespace-cascade branch — pull the sections below into
the PR body, or lift pieces of it into the individual commit messages that
land the work, so the generated changelog reads coherently.

## Breaking: namespaces always read their ancestors now

**The single most important behavior change**: a request in a nested
namespace now _always_ reads its ancestors' durable (semantic/procedural)
memories. `acme/phoenix/api` reads `acme/phoenix` and `acme` on every
`scope: "full"` recall/briefing (the default), with zero configuration.

This replaces four separate, partially-overlapping mechanisms
(`MEMINI_GLOBAL_NAMESPACE`, the opt-in `MEMINI_TENANT_SHARED` + `<tenant>/_shared`
convention, `scope=subtree`, explicit `namespaces: [...]`) with one rule that
works at any depth. The old **opt-out is gone**: previously,
`MEMINI_TENANT_SHARED=false` (the default) meant a nested namespace read
_only_ itself, with sharing entirely opt-in. Under the cascade there is no
equivalent switch — ancestor sharing is unconditional for any namespace with
a `/` in it. If you were relying on `MEMINI_TENANT_SHARED` staying off to
keep a hierarchical namespace fully isolated from its parent, that isolation
no longer holds by default; use `scope: "project"` per call if a specific
read needs to stay primary-only.

Everything else about the old default read behavior is a strict subset of
the new cascade — the ancestor cascade only _adds_ what a nested namespace
sees, it never removes anything a flat namespace already read.

## Deleted config, boot-time refusal, and migration

`MEMINI_GLOBAL_NAMESPACE` and `MEMINI_TENANT_SHARED` are deleted. The server
refuses to start when either is set in the environment, with a message
pointing at `memini migrate scopes` — fail loud, since memini is pre-1.0.

Run `memini migrate scopes` to move forward:

1. Every `<tenant>/_shared` namespace (the old opt-in tenant-shared
   convention) is merged into `<tenant>` — interior namespaces are now the
   shared layer directly, so the old sibling convention has nowhere else to
   live. A dedup pass runs after each merge to collapse any facts the move
   just duplicated. Defaults to a dry-run report; pass `--yes` to apply.
2. If `MEMINI_GLOBAL_NAMESPACE` was set, the command does **not** silently
   rewrite it (a single shared namespace could mean different things to
   different operators) — it prints adoption instructions instead: for a
   single-operator instance, set `MEMINI_HOME=<old global>`; for a
   team-shared one, `memini link add <ns> <old global>` for each namespace
   that needs it.
3. A bare `_shared` namespace (no tenant prefix) has no parent to merge into
   and is left alone, reported as a note — it's likely meant to become
   someone's home namespace or a link endpoint.

The command is idempotent: once no `<tenant>/_shared` namespace holds any
memories, re-running finds nothing to do.

## New: personal namespaces (`MEMINI_HOME`)

A new client-side env var, `MEMINI_HOME` (recommended value
`personal/<name>`), gives every person on a shared instance their own
"everywhere" namespace — a per-person replacement for the old
instance-global `MEMINI_GLOBAL_NAMESPACE`. Resolved by the plugin exactly
like `MEMINI_NAMESPACE` and sent as `X-Memini-Home` on every call (or read
directly from the env var on stdio MCP, which has no headers). Durable
memories in your home namespace merge read-only into every recall/briefing;
`memory_remember(..., visibility: "personal")` writes there directly.

## New: `visibility` on writes

`memory_remember` (and `POST /v1/memories`) gains `visibility`: `"project"`
(default, stays in the primary namespace), `"personal"` (routes to the
caller's home namespace), or an ancestor's name (routes durable writes up
the chain — matched by full path or an unambiguous last segment). Episodic
and working writes are always clamped to the primary namespace regardless of
`visibility`, silently — this is what stops session digests from polluting
a shared ancestor. An unrecognized or ambiguous ancestor name errors with
the valid chain listed, e.g.
`remember: visibility "widgets" not in scope; valid: project, personal, acme/phoenix, acme` —
the error is written to teach the topology to an LLM caller, not just a
human.

## New: `scope` on reads

`memory_recall`, `memory_briefing`, and `memory_answer` gain `scope`:
`"project"` (primary only), `"full"` (default: the ancestor/home/link
cascade), or `"everywhere"` (full, plus the primary namespace's own
subtree). The REST API keeps the old `"exact"`/`"subtree"` values as
deprecated aliases for back-compat (`"exact"` → `"project"`, `"subtree"` →
`"everywhere"`); MCP speaks the new vocabulary only.

## New: namespace links

`memini link add|rm|ls` (and `POST/GET/DELETE /v1/links`) create durable-tier,
one-hop read edges between namespaces that aren't in an ancestor/descendant
relationship — lateral sharing for e.g. two unrelated projects that share a
convention. No transitive traversal: a link's destination doesn't inherit
anything the destination itself links to.

## New: provenance on every result

Every recall/briefing/answer result now carries a `from` field: empty for a
hit from the primary namespace, the bare namespace for an ancestor or home
hit, `link:<ns>` for a linked namespace, `call:<ns>` for an explicit
per-call namespace. This is how an LLM caller learns the topology of a
shared instance without ever constructing or seeing a raw namespace path
itself — by reading where its own results came from.

## New: briefing scope line

`memory_briefing` now opens with a one-line scope summary showing the
resolved cascade and how many memories each leg contributed, e.g.:

```
Scope: acme/phoenix/api ← acme/phoenix(3) ← acme(4) ← personal(2), +1 link
```

At an interior namespace, briefing also appends a compact rollup of direct
child namespaces — name, memory count, and pinned/recent highlights (MCP
renders these as compact display titles to keep token size down; REST
carries the full memory objects for the admin UI) — orientation only, not a
precision change to recall.

## New: `memini doctor` additions

`memini doctor` now shows the effective read set for the current namespace,
warns when `MEMINI_NAMESPACE` is pinned globally (the "catch-all namespace"
trap), and warns when `MEMINI_HOME` is unset while `visibility: "personal"`
has been attempted recently.

## New: `GET /v1/namespaces/read-set`

A read-set introspection endpoint: header-scoped like `/v1/namespaces/briefing`
(no path parameter — the namespace comes from `X-Memini-Namespace`, home from
`X-Memini-Home`), it returns the resolved structural read set — namespace,
origin (`primary`/`ancestor`/`home`/`link`), and tier restriction — for
debugging what a given namespace/home pair actually sees.
